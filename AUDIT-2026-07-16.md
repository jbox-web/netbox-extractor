# netbox-extractor — Audit de code

Scope : sources écrites à la main (`src/` 58 fichiers / 3569 lignes, `templates/` 7, config d'exemple, CLI, CI, Dockerfile, README) · Couverture : **70/70 fichiers production lus + 11 specs (méta)**, `vendor/` (2369 fichiers générés OpenAPI) exclu.
Date : 2026-07-16 · Ré-audit (le code porte les marqueurs C*/K*/S*/P* d'un audit antérieur, `AUDIT.md` supprimé).

Sémantique vérifiée empiriquement ce tour-ci (probes compilées, Crystal 1.20.3) :
- `Process.run(cmd, shell: true, args: [...])` passe `args` comme argv réel (`;`, `$HOME` sortis littéralement) → **pas d'injection shell** par les args ; lève `ArgumentError` seulement si `command` contient déjà des arguments.
- `Array(YAML::Any) & Array(String)` **matche** (`YAML::Any#hash`/`#==` délèguent à la valeur brute) → le filtre d'exclusion par tag fonctionne.
- `receiver.try &.a.b || fallback` : le `|| fallback` est **hors** du bloc `&.` → `netbox_primary_ip`/`netbox_os_name` retombent bien sur leur défaut quand le receveur est nil.

## État de la remédiation au 2026-08-06

Légende : ✅ traité · ⛔ finding invalidé (l'analyse était fausse) · ⬜ non traité.

Commits : `ded1e99` (CI/mise alignés sur les gabarits) · `1c7a0cd` (macros Icinga et fuite de tokens) · `44df0db` (pertes silencieuses à la génération).

Deux corrections au rapport lui-même, établies en traitant les findings :

- **Le finding sur les credentials non quotés (SEC-generic-host.j2:51) est faux.** Ces champs portent le **nom d'une constante Icinga2** déclarée dans `constants.conf` (`password = JAGUAR_POSTGRES_PASS`), pas un littéral. Les quoter transforme la référence en la chaîne `"JAGUAR_POSTGRES_PASS"` : le check reçoit le nom de la constante au lieu de sa valeur, **sans aucune erreur de parse pour le signaler**. Le bareword est donc intentionnel sur les cinq blocs. Vérifié sur une sortie de production. Un spec verrouille désormais le bareword dans les deux sens, et le template porte l'explication. La limite subsiste : un credential littéral contenant une espace ou un guillemet reste inécrivable — il doit passer par une constante.
- **La mention « zéro spec pour crinja_filters » (TEST) était inexacte** : `utils_spec.cr` couvrait déjà l'échappement des guillemets, backslashes et sauts de ligne. Seul le cas `$` manquait.

Un défaut absent du rapport, découvert et corrigé en chemin : dans un module inclus, la constante `Log` se résout **lexicalement**, donc tous les avertissements de `InventoryFilters` et `IcingaHelper` (dont « unsafe name », préexistant) partaient sur le logger racine à source vide — inattribuables et hors de portée d'un niveau par source. Vérifié par sonde compilée. Les deux mixins portent maintenant leur propre source nommée.

**Aucun finding CRITICAL.** Le socle défensif est solide : `each_isolated` ré-émet une `PartialFailure` (exit ≠ 0) au lieu d'avaler les échecs de fibre ; pagination correcte (`offset += page.results.size`, `break` sur page vide) ; build-then-swap Icinga ; chargements Netbox ré-émettant l'erreur avant toute régénération destructive ; noms d'hôtes filtrés (`SAFE_NAME`) avant toute construction de chemin.

## 2. Concurrency

Solide dans l'ensemble — analysé à travers la frontière de fibre : `icinga_staging_path` posé une seule fois sur l'objet `@site` (distinct par site) avant le fan-out, lu seulement ensuite ; `Log.context.set` rappelé dans chaque fibre (fiber-local) ; cache de templates gardé par `Mutex` ; client Netbox et env CRINJA construits avidement au load (pas de `||=` racé). ## Hypothèses vérifiées et écartées (avec preuve)

- **Injection shell via `ansible-playbook`** (facts_fetcher/ansible.cr:149) — écartée. Probe : `Process.run("echo", shell: true, args: ["c;d","$HOME"])` sort `c;d $HOME` littéralement ; les args sont de l'argv réel, pas du texte shell. `shell: true` est un surcoût inutile, pas une faille.
- **Path traversal via nom d'hôte** (icinga_host.cr:29 / netbox_device.cr:37 / netbox_vm.cr:30) — écartée. `InventoryFilters.valid_object_name?` rejette tout nom hors `/\A[A-Za-z0-9._-]+\z/` (donc tout `/`) AVANT les présenteurs (filter_objects dans fetch_devices/fetch_vms). Sans `/`, `File.join` ne peut pas s'échapper ; `..` seul devient `...conf`.
- **Nom d'hôte null → `role/.conf` en collision** (netbox_device.cr:37) — écartée. Les noms nil/vides sont supprimés par valid_object_name? avant toute construction de chemin.
- **VM rôle null → chemin `-linux/`** (netbox_vm.cr:30) — écartée. `netbox_has_role?(role)` = `netbox_role == role` ; une VM à rôle nil n'apparie aucun vm_role configuré → jamais sélectionnée → n'atteint jamais netbox_icinga_filename.
- **Exclusion par tag inopérante** (facts_fetcher:128, `Array(YAML::Any) & Array(String)`) — écartée. Probe : l'intersection renvoie l'élément (`["exclude-me"]`), `YAML::Any#hash`/`#==` délèguent à la valeur brute.
- **`netbox_primary_ip`/`netbox_os_name` ne retombent pas sur leur défaut** (précédence `try &. ... || fallback`) — écartée. Probe : receveur nil → renvoie le fallback (`|| ` hors du bloc `&.`).
- **`PartialFailure` avalée → exit 0 sur échec partiel** — écartée. `each_isolated` (concurrency.cr:50) ré-émet après le fan-out ; le runner admiral ne rescue qu'`Admiral::Error` → propagation jusqu'à un exit ≠ 0 dans les deux modes d'env.
- **Pagination sautant des blocs / bouclant à l'infini** — écartée. `offset += page.results.size` (pas `+= limit`) et `break` sur page vide ; `concat` (pas `+=`) donc pas d'O(n²).
- **Régénération destructive sur résultat vide dû à un échec de chargement** — écartée. `define_netbox_load` ré-émet ApiError/IO/Socket/ParseException avant tout `File.delete`/`rm_rf` ; le swap Icinga n'a lieu qu'après un chargement réussi.
- **Templates re-parsés par hôte** — écartée. `Utils.render_template` cache le `Crinja::Template` compilé par source sous mutex ; templates servis depuis un BakedFileSystem en mémoire.
- **`exclude["exclude_volumes"]` KeyError / type-crash** — écartée. Clé toujours présente dans `Partitions#to_h` ; `Array(String) - Array(String)` type-check.
- **Config d'exemple non chargeable (propriété requise manquante)** — écartée. Toutes les propriétés requises sans défaut (dont l'objet imbriqué `Ansible::Site.fetch_facts`) sont fournies par netbox-extractor.yml.example.
- **Héritage `site.x || global.x` lossy pour Bool/Int** — écartée. Les bools héritables utilisent `Bool?` + check `nil?` explicite (facts_fetcher:61-64) ; les `Int32?` via `||` sont sûrs (Crystal traite `0` comme truthy, seul `nil` retombe).
